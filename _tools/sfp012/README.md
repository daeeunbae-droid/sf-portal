# SFP-012 회귀 테스트

`SF_Word_Test_20.html`(고등단어장 어원편 소스 추가)의 jsdom 검증 스크립트.
SFP-004-P의 "클릭 시뮬레이션으로 라우팅 검증" 관례를 그대로 따른다.

## 실행

```bash
cd _tools/sfp012 && npm install && node verify.js
```

`SF_Word_Test_19.html`과 `SF_Word_Test_20.html`이 모두 저장소 루트에 있어야 한다.
**19를 "정답지"로 놓고 20과 대조**하는 구조라, 19를 지우면 A 섹션(무변경 확인)이 못 돌아간다.

종료 코드 0 = 전체 통과. 마지막 줄에 `PASS n / FAIL n`이 찍힌다.
기준선: **59 PASS / 0 FAIL** (2026-08-06, 20.html 최초 작성 시점)

## 무엇을 보는가

| 섹션 | 내용 |
|---|---|
| A | `gbo()` 단원 순서를 19와 대조. Voca 3000 `p1~p148`·RL 목록 무변경, 고등단어장 67단원이 `DAY 01…DAY 60` + 부록 7 순서인지. `WB["Voca 3000"]`/`RL`/`VOCA_SENTENCE_DATA` 완전 동일 확인 |
| B | 로그인 → 소스 선택 화면에 카드 3개 |
| C | 고등단어장 카드 → 3모드 화면. 오답 다시 풀기 카드가 비활성이고 클릭해도 진입 안 되는지 |
| D | 익히기 진입 → DAY 단원 67개 즉시 노출 → 단원 선택 → 학습 문항 생성 |
| E | 확인하기 진입 → 오답 제출이 `voca3000/{학생}/wrong/` 노드를 오염시키지 않는지 |
| F | **회귀** — Voca 3000 경로(단원 목록·오답 누적·나가기·소스 변경·소스 왕복 전환) |
| G | **회귀** — 모의고사 단어(문장형) 경로 |

F/G가 이 스크립트의 핵심이다. 소스를 하나 더 붙일 때 기존 두 경로가 깨지지 않는지가 가장 중요하다.

## 주의

- 하네스가 firebase CDN `<script>`를 제거하고 돌리므로 앱은 **오프라인 모드**(`memStore`)로 동작한다.
  Firebase 실경로는 이걸로 검증되지 않는다 — 실기기 확인이 따로 필요하다.
- `WB`/`S`/`RL` 등은 스크립트 최상위 `const`/`let`이라 `window`에 안 올라간다.
  테스트에서 `w.eval("S")`로 꺼내 쓰는 이유가 이것.
- 모드 카드는 `c.onclick()`을 직접 호출한다(jsdom에서 실제 클릭 이벤트 대신).

## build_wb.js

엑셀 → `WB["고등단어장 어원편"]` 주입 스크립트. 20.html을 만들 때 쓴 것을 재생성용으로 남겨둔 것이다.

```bash
node build_wb.js "<엑셀경로>" [출력파일]
```

**19에서 새로 생성해 덮어쓰므로, 실행하면 20.html의 UI 수정(소스 카드·`gbo()` 정렬 등)이 날아간다.**
데이터만 다시 뽑고 싶을 때 쓰고, 결과를 그대로 배포하지 말 것.

엑셀 경로는 필수 인자다. 원본 파일명 자체에 출판사 상품명이 들어 있어서 코드에 기본값을 박지 않았다.
원본 엑셀은 출판사 저작물이라 저장소에 커밋하지 않는다(`.gitignore`의 `*.xlsx`). 로컬에만 두고 쓴다.

앱에 노출되는 라벨은 `고등단어장 어원편`이다. 출판사 상품명은 저장소·서비스 페이지 어디에도 넣지 않는다.
